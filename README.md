# Customer Segmentation with RFM Analysis

Сегментация клиентов интернет-магазина на основе RFM-анализа и кластеризации.
Проект сравнивает KMeans и DBSCAN и показывает, почему для этой задачи выбран KMeans.

---

## Бизнес-задача

Интернет-магазин хочет перейти от массовых рассылок и одинаковых скидок
к **персонализированным маркетинговым кампаниям**. Для этого нужно разбить
клиентов на группы со схожим покупательским поведением и для каждой группы
разработать свою стратегию.

---

## Данные

- **Источник:** Online Retail Dataset (UCI / Kaggle)
- **Объём:** 541 909 транзакций, 8 колонок
- **Период:** 01.12.2010 — 09.12.2011 (373 дня)
- **Колонки:** `InvoiceNo`, `StockCode`, `Description`, `Quantity`,
  `InvoiceDate`, `UnitPrice`, `CustomerID`, `Country`
- **После очистки:** 392 692 транзакции, **4 338 уникальных клиентов**

**Очистка включала:**
- удаление дубликатов;
- удаление пропусков;
- удаление возвратов (`Quantity < 0`);
- удаление некорректных цен (`UnitPrice ≤ 0`);
- удаление транзакций без `CustomerID`.

---

## Методы

1. **EDA** — первичный анализ данных, распределения, выбросы.
2. **Feature Engineering** — `TotalPrice = Quantity × UnitPrice`.
3. **RFM-анализ** — расчёт `Recency`, `Frequency`, `Monetary` по каждому клиенту.
4. **Log-трансформация** (`np.log1p`) — сжатие выбросов и правых хвостов.
5. **Стандартизация** (`StandardScaler`) — приведение признаков к одному масштабу.
6. **Выбор числа кластеров:**
   - метод локтя;
   - **silhouette score** для k = 2, 3, 4, 5.
7. **Кластеризация KMeans** (k = 3).
8. **Проверка устойчивости через DBSCAN** — для поиска выбросов и сравнения методов.
9. **Визуализации:** boxplots до/после log1p, scatter-проекции, pairplot.

---

## Обоснование выбора k = 3

| k | silhouette | inertia |
|---|---|---|
| 2 | **0.434** | 6502.1 |
| 3 | 0.339 | 4893.3 |
| 4 | 0.336 | 3987.6 |
| 5 | 0.315 | 3371.5 |

Silhouette максимален при **k = 2**, но k = 3 даёт более полезную бизнес-
сегментацию при небольшой потере формального качества:
- k = 2 разделил бы клиентов только на «активных» и «неактивных»;
- k = 3 дополнительно выделяет **VIP-сегмент**, который критически важен для
  бизнеса и подтверждается визуально (scatter, pairplot).

Итоговый выбор — **k = 3**.

## Сравнение с DBSCAN

**Параметры:** `eps = 0.5`, `min_samples = 6`.

**Результат:** DBSCAN **не смог выделить VIP-сегмент**:

| | Клиентов |
|:---|---:|
| Кластер 0 (ядро) | 2 786 |
| Кластер 1 (ядро) | 1 485 |
| Микро-кластер 2 | 2 |
| Шум (−1) | 65 |

**Что произошло с 732 VIP-клиентами KMeans:**
- 686 — «слились» в общий кластер вместе с обычными клиентами;
- 44 — попали в шум;
- **только 2** — выделены в отдельный кластер.

**Вывод:** DBSCAN не подходит для этой задачи, поскольку RFM-пространство
после log1p + StandardScaler не имеет чёткой плотностной структуры
(на k-distance графике нет выраженного «колена»). KMeans работает лучше,
потому что опирается на центроид, а не на локальную плотность, и способен
выделить разреженный, но бизнес-значимый VIP-сегмент.

DBSCAN оказался полезен **как инструмент проверки**: он подтвердил, что
VIP-клиенты — это гетерогенная группа с большим разбросом по тратам.

## Бизнес-рекомендации

| Сегмент | Размер | Профиль | Рекомендации |
|:---|---:|:---|:---|
| **0 — Постоянные** | 38.9 % | ~3.5 заказа, 1 399 трат, покупка ~46 дней назад | Программа лояльности, бонусы за повторные покупки, email-рассылки с новинками |
| **1 — Уходящие** | 44.2 % | ~1.3 заказа, 351 трат, покупка ~161 день назад | Реактивационные кампании, персональные скидки, напоминания, «мы скучаем» |
| **2 — VIP** | 16.9 % | ~13.6 заказов, 7 994 трат, покупка ~13 дней назад | Персональный менеджер, эксклюзивные предложения, бесплатная доставка, ранний доступ к новинкам |

**Дополнительно:** 65 клиентов с аномальным профилем (шум DBSCAN) —
средний чек 42 331, медиана 21 429. Требуют отдельного анализа:
возможно, это оптовые или B2B-закупки.
